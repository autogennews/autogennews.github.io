# LangChain4j overview: September 2 – October 1, 2026

**Caveat on sources.** My search tool couldn't open the GitHub release pages directly, so I haven't read the official release notes or individual PRs for any of the three repos. Everything below comes from secondary sources: InfoQ, blogs, dependency trackers, and other projects' changelogs. I've marked how sure I am of each point. Check the release pages before acting on this, especially the breaking-changes section.

## 1. Short summary

- **Releases in the period (main repo):**
  - **1.20.0** (with 1.20.0-beta30), published September 4. This is the only big release of the month.
  - **1.19.1 and 1.19.2**, both September 7. Per a third-party summary of the repo, **1.19.1 was published in error and shouldn't be used**.
  - **1.20.1 and 1.20.2**, both before September 28. I can only see them because another project's automated dependency-update bot bumped to them. Exact dates and contents are unknown.
- **Main theme: non-blocking and reactive AI services.** In 1.20.0, AI service methods can experimentally return `CompletableFuture<T>` and `Flow.Publisher<T>` instead of blocking a thread for the whole interaction. This fits a wider push: Quarkus is also doing a non-blocking rewrite of its LangChain4j integration, end to end.
- **Second theme: the Jackson 3 / Spring Boot 4 generation.** 1.20.0 adds opt-in support for Jackson 3 behind its JSON plug-in interface (SPI), and separate Spring Boot 4 starters exist (e.g., `langchain4j-ollama-spring-boot4-starter`).
- **Agents and decision-making.** A new core abstraction, `StructuredDecisionModel` (earlier name: `JudgeModel`), was proposed in PR #6469 on September 19, with a matching provider PR in langchain4j-community. I couldn't confirm whether it was merged or released.
- **Release churn.** A withdrawn release (1.19.1), a parallel 1.19.x patch line and two quick 1.20.x patches suggest pinning exact versions.
- **langchain4j-spring and langchain4j-community** appear to follow the main version (1.20.0-beta30 community artifacts were on Maven Central by September 5). I couldn't find release notes for either repo.

## 3. Breaking changes and deprecations

**I couldn't verify a breaking-changes or deprecations list for any of these releases.** Known risks:
- **Don't use 1.19.1** (reported as published in error). If you're on the 1.19.x line, use 1.19.2.
- **Reactive return types are experimental.** The API may change in later minor versions, so don't build core contracts on it yet.
- **Jackson 3 support is opt-in,** so the default should stay on Jackson 2. I couldn't verify whether any default changed.
- **Spring Boot 3 vs 4:** make sure you use the right starter name (`...-spring-boot-starter` for Boot 3, `...-spring-boot4-starter` for Boot 4). Mixing them is a likely source of classpath problems.
- **Spring and community modules stay on `-betaNN` versions** (1.20.0-beta30) while core is GA. Their APIs are less stable.
- **1.20.1 and 1.20.2:** contents unknown. They could include regression fixes for 1.20.0, so read their notes before going to production on 1.20.0.

## 4. What's worth trying or adopting

1. **Upgrade to the latest 1.20.x patch (1.20.2) instead of 1.20.0,** after reading its notes. It picks up patches soon after a large release. Pin exact versions.
2. **Pilot the reactive AI services on a non-critical path** if you use WebFlux, Vert.x or virtual threads. It could remove thread blocking, but it's experimental, so keep it behind a feature flag.
3. **Try the Jackson 3 opt-in** if you're planning a move to Spring Boot 4 / Spring Framework 7. It's a prerequisite for that migration.
4. **Try Anthropic native JSON Schema output** if you use Claude for structured output. The documentation describes prompt-only structured output as "quite unreliable."
5. **Watch PR #6469 (`StructuredDecisionModel`).** It would be useful for routing, classification and LLM-as-judge in agents, but wait for a release.

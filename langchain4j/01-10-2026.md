# 1. Brief summary

**Scope:** In 2 Sep – 1 Oct 2026 the core and Spring repos each had six releases: 1.20.0 (4 Sep), 1.19.1 (7 Sep, published in error), 1.19.2 (7 Sep), 1.19.3 (15 Sep), 1.20.1 (25 Sep) and 1.20.2 (28 Sep) ([core 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=Non%2Dblocking%20%2F%20reactive%20support), [core 1.19.1](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1#:~:text=This%20release%20was%20published%20by%20mistake.)). The Spring tags carry a `-beta30` or `-beta29` suffix ([Spring 1.20.0-beta30](https://github.com/langchain4j/langchain4j-spring/releases/tag/1.20.0-beta30#:~:text=Reactor%20support%20for%20the%20non%2Dblocking%20AI%20Service%20modes)). Community had one release, 1.20-beta30 (4 Sep) ([community 1.20-beta30](https://github.com/langchain4j/langchain4j-community/releases/tag/1.20-beta30#:~:text=Add%20Amazon%20DynamoDB%20embedding%20store)). The headline of 1.20.0 is non-blocking AI Services: a method can return `CompletableFuture` or `Flow.Publisher`, and the call then runs without holding a thread ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=nothing%20else%20about%20the%20interface%20changes)). The feature is additive but marked experimental ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=The%20work%20is%20additive%20and%20marked)). It works only with providers that implement the non-blocking SPI; every other provider fails loudly instead of falling back to blocking ([PR #5527](https://github.com/langchain4j/langchain4j/pull/5527#:~:text=and%20fails%20loudly%20on%20the%20non%2Dblocking%20path%20until%20it%20opts%20in)). The second headline is an opt-in Jackson 3 module, `langchain4j-jackson3`; removing the dependency puts everything back on Jackson 2 ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=removing%20the%20dependency%20puts%20everything%20back%20on%20Jackson%202)). The Spring repo followed with Reactor bindings and an optional Spring-executor integration for the non-blocking mode ([Spring PR #211](https://github.com/langchain4j/langchain4j-spring/pull/211#:~:text=This%20adds%20the%20Reactor%20bindings%20for%20that%2C%20plus%20the%20piece%20a%20Spring%20Boot%20application%20needs%20to%20make)). MCP work was substantial: the Jackson types were removed from the client contracts and the old Jackson-typed methods were deprecated ([PR #6117](https://github.com/langchain4j/langchain4j/pull/6117#:~:text=deprecates%20the%20Jackson%2Dtyped%20ones)). There were also many MCP robustness fixes, such as cancelling pending operations on timeouts ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=cancel%20pending%20operations%20and%20notify%20server%20on%20read%2Fprompt%2Fsubscribe%20timeouts)). The agentic module gained A2A human-in-the-loop resumption and multi-tenant routing ([PR #6038](https://github.com/langchain4j/langchain4j/pull/6038#:~:text=Allows%20callers%20to%20resume%20the%20existing%20remote%20task%20by%20invoking%20the%20agent%20again%20with%20the%20IDs%20exposed%20by%20the%20exception.), [release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=for%20multi%2Dtenant%20agent%20routing)). Provider and integration work covered Gemini context caches, an extended watsonx module, a richer Docling parser and a new DynamoDB vector store in community ([PR #5725](https://github.com/langchain4j/langchain4j/pull/5725#:~:text=This%20adds%20the%20missing%20creation%20half.), [PR #6209](https://github.com/langchain4j/langchain4j/pull/6209#:~:text=It%20also%20includes%20several%20minor%20breaking%20changes%20to%20align%20the%20API%20with%20the%20rest%20of%20LangChain4j.), [PR #6255](https://github.com/langchain4j/langchain4j/pull/6255#:~:text=Non%2Dblocking%20parsing.), [community PR #755](https://github.com/langchain4j/langchain4j-community/pull/755#:~:text=single%2Ddigit%20millisecond%20latency)). On the cleanup side, the GitHub Models module and both Spring starters were removed because the service was retired ([PR #5692](https://github.com/langchain4j/langchain4j/pull/5692#:~:text=being%20fully%20retired%20on%20July%2030%2C%202026), [Spring PR #210](https://github.com/langchain4j/langchain4j-spring/pull/210#:~:text=Applications%20that%20declare%20either%20of%20these%20dependencies%20will%20fail%20to%20resolve%20after%20this%20release)). A release-process incident also happened: 1.19.1 (core) and 1.19.1-beta29 (Spring) were published by mistake and contain code from `main` ([Spring 1.19.1-beta29](https://github.com/langchain4j/langchain4j-spring/releases/tag/1.19.1-beta29#:~:text=silently%20drops%20two%20published%20starters)). Finally, 1.19.2 and 1.19.3 are MCP-backport patch lines for teams staying on 1.19.x ([1.19.2](https://github.com/langchain4j/langchain4j/releases/tag/1.19.2#:~:text=1.19.1%20MCP%20backports), [1.19.3](https://github.com/langchain4j/langchain4j/releases/tag/1.19.3#:~:text=1.19%20mcp%20backports)).

# 2. Key highlights

## Core: platform and runtime
- **Non-blocking / reactive AI Services (`@Experimental`).** You select the mode by return type: `CompletableFuture`/`CompletionStage` for a single response, or `Flow.Publisher` for streaming. Non-blocking extends through tools, chat memory, guardrails and the retrieval graph ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=nothing%20else%20about%20the%20interface%20changes)). Provider support is OpenAI (Chat Completions and Responses), Anthropic and Bedrock. All others fail loudly ([PR #5527](https://github.com/langchain4j/langchain4j/pull/5527#:~:text=and%20fails%20loudly%20on%20the%20non%2Dblocking%20path%20until%20it%20opts%20in)).
- **Different defaults on the async path.** Multiple tool calls run concurrently, a tool execution error fails the invocation, and an argument-parse error goes back to the LLM ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=A%20few%20defaults%20deliberately%20differ%20on%20the%20async%20path)).
- **ThreadLocal context is not propagated across the async hops.** MDC, tracing and security context need a context-propagating `ExecutorProvider` ([PR #5527](https://github.com/langchain4j/langchain4j/pull/5527#:~:text=Thread%2Dlocal%20context%20does%20not%20follow%20the%20async%20hops)).
- **Jackson 3 opt-in.** Chat memory, `InMemoryEmbeddingStore` files and persisted `AgenticScope` state written by Jackson 2 stay readable under Jackson 3 ([PR #6184](https://github.com/langchain4j/langchain4j/pull/6184#:~:text=Stored%20data%20stays%20readable.)). The PR also fixed several silent latent defects found during the migration ([PR #6184](https://github.com/langchain4j/langchain4j/pull/6184#:~:text=That%20surfaced%20defects%20that%20were%20already%20latent)).

## Agents, A2A and MCP
- **A2A human-in-the-loop resume.** When a remote agent is paused for input or auth, the interrupted-task exception now carries the IDs needed to resume the task ([PR #6038](https://github.com/langchain4j/langchain4j/pull/6038#:~:text=Allows%20callers%20to%20resume%20the%20existing%20remote%20task%20by%20invoking%20the%20agent%20again%20with%20the%20IDs%20exposed%20by%20the%20exception.)).
- **A2A multi-tenant routing.** Adds `@A2ATenantId` ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=for%20multi%2Dtenant%20agent%20routing)). The PR also upgrades the A2A SDK from 1.1.0 ([PR #6303](https://github.com/langchain4j/langchain4j/pull/6303#:~:text=Upgrade%20A2A%20SDK%201.1.0)).
- **Agentic improvements.** Agent argument descriptions are now preserved ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=preserve%20agent%20argument%20descriptions)). The `ObjectMapper` ClassLoader for `AgenticScope` serialization is configurable, and this is also in 1.19.3 ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=Allow%20to%20configure%20ClassLoader%20on%20the%20ObjectMapper%20used%20for%20AgenticScope%20serialization), [1.19.3](https://github.com/langchain4j/langchain4j/releases/tag/1.19.3#:~:text=Allow%20to%20configure%20ClassLoader%20on%20the%20ObjectMapper%20used%20for%20AgenticScope%20serialization)).
- **`@McpClientSupplier` may now take parameters (1.20.1).** Before, such a supplier was skipped and agent building failed ([release 1.20.1](https://github.com/langchain4j/langchain4j/releases/tag/1.20.1#:~:text=to%20also%20have%20supplier%20parameters), [PR #6505](https://github.com/langchain4j/langchain4j/pull/6505#:~:text=had%20to%20declare%20zero%20parameters)).
- **MCP hardening in 1.20.0.** Examples: fail fast when the retried request gets 404 again after session reinitialization, and subscribeToResources now waits for the server's acknowledgement ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=fail%20fast%20when%20the%20retried%20request%20gets%20404%20again%20after%20session%20reinitialization), [release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=Make%20subscribeToResources%20wait%20for%20the)).

## Providers, RAG and document parsing
- **Gemini context caches.** `GeminiCaches` adds the missing creation half (create, get, list, delete) ([PR #5725](https://github.com/langchain4j/langchain4j/pull/5725#:~:text=This%20adds%20the%20missing%20creation%20half.)). Update/TTL refresh is not included; the TTL is set at creation ([PR #5725](https://github.com/langchain4j/langchain4j/pull/5725#:~:text=The%20TTL%20is%20set%20at%20creation)).
- **watsonx.** New Gateway embedding and image models, streaming cancellation and inline chat moderation ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=streaming%20cancellation%2C%20and%20inline%20chat%20moderation)). Cancelling aborts the in-flight HTTP stream immediately ([PR #6209](https://github.com/langchain4j/langchain4j/pull/6209#:~:text=so%20the%20in%2Dflight%20HTTP%20stream%20is%20aborted%20immediately)).
- **Bedrock.** Request metadata is supported in the Converse APIs ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=support%20request%20metadata%20in%20Converse%20APIs)).
- **Docling parser.** Operation selection via a `DocumentRequest` template, async parsing and a custom request executor ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=DocumentRequest%20templates%2C%20async%20parsing%2C%20and%20custom%20request%20executor)). The default invocation now targets async endpoints ([PR #6255](https://github.com/langchain4j/langchain4j/pull/6255#:~:text=The%20default%20invocation%20now%20targets%20the%20async%20convert%2Fchunk%20endpoints)).
- **Jina.** Supports the per-call embedding INPUT_TYPE parameter ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=per%2Dcall%20embedding%20parameter)).

## Spring starters (langchain4j-spring)
- **Reactor bindings.** `Mono` and `Flux<AiServiceStreamingEvent>` return types for the non-blocking modes ([Spring release 1.20.0-beta30](https://github.com/langchain4j/langchain4j-spring/releases/tag/1.20.0-beta30#:~:text=Reactor%20support%20for%20the%20non%2Dblocking%20AI%20Service%20modes)). `Flux<String>` is deliberately left on the old path ([Spring PR #211](https://github.com/langchain4j/langchain4j-spring/pull/211#:~:text=is%20deliberately%20left%20alone)).
- **Spring executor for offloaded work.** This is the `langchain4j.executor.use-spring-task-executor=true` property, off by default on purpose ([Spring PR #211](https://github.com/langchain4j/langchain4j-spring/pull/211#:~:text=Off%20by%20default%20on%20purpose)). It matters because LangChain4j does not copy ThreadLocal state across its thread hops ([Spring PR #211](https://github.com/langchain4j/langchain4j-spring/pull/211#:~:text=That%20matters%20because%20LangChain4j%20does%20not%20copy)).
- **Starter test coverage.** Every property of the OpenAI and Anthropic starters is now tested, "and fix what that uncovered" ([OpenAI](https://github.com/langchain4j/langchain4j-spring/releases/tag/1.20.0-beta30#:~:text=Test%20every%20property%20of%20the%20OpenAI%20starters%2C%20and%20fix%20what%20that%20uncovered), [Anthropic](https://github.com/langchain4j/langchain4j-spring/releases/tag/1.20.0-beta30#:~:text=Test%20every%20property%20of%20the%20Anthropic%20starters%2C%20and%20fix%20what%20that%20uncovered)). The release notes don't say which fixes this involved (see section 4).

## Community
- **Amazon DynamoDB embedding store.** It uses native vector search and is positioned for single-digit-millisecond latency ([community PR #755](https://github.com/langchain4j/langchain4j-community/pull/755#:~:text=single%2Ddigit%20millisecond%20latency)). Filtering is equality-only ([community PR #755](https://github.com/langchain4j/langchain4j-community/pull/755#:~:text=and%20only%20with%20equality)).
- **Other additions.** A Xquik research tool, DashScope support for qwen3.8-max and qwen-image-3.0, and a Cohere `TokenCountEstimator` ([add Xquik research tool](https://github.com/langchain4j/langchain4j-community/releases/tag/1.20-beta30#:~:text=add%20Xquik%20research%20tool), [DashScope](https://github.com/langchain4j/langchain4j-community/releases/tag/1.20-beta30#:~:text=add%20support%20for%20qwen3.8%2Dmax%20and%20qwen%2Dimage%2D3.0), [Cohere](https://github.com/langchain4j/langchain4j-community/releases/tag/1.20-beta30#:~:text=Implement%20TokenCountEstimator%20for%20Cohere%20integration)).

# 3. Breaking changes and deprecations

**Release hygiene (act first)**
- **Do not use core 1.19.1 or Spring 1.19.1-beta29.** They were cut from `main`, not `release/1.19.x`, and sit 108 commits and 300 files ahead of 1.19.0 ([core 1.19.1](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1#:~:text=108%20commits%20and%20300%20files)).
- **If you are already on 1.19.1, go to 1.20.0 or later, not 1.19.2.** 1.19.2 contains less code, so moving there would silently remove functionality ([core 1.19.1](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1#:~:text=would%20silently%20remove)).
- **Version-comparison tools can pick 1.19.1 as a baseline.** Tools that choose "the newest release below X" will select it and report misleading API differences ([core 1.19.1](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1#:~:text=will%20select%20it%20and%20report%20misleading%20API%20differences%20for%20any)).
- **Spring 1.19.1-beta29 has no GitHub Models starters.** It silently drops the two starters ([Spring 1.19.1-beta29](https://github.com/langchain4j/langchain4j-spring/releases/tag/1.19.1-beta29#:~:text=silently%20drops%20two%20published%20starters)). They are published again in 1.19.2-beta29 ([same](https://github.com/langchain4j/langchain4j-spring/releases/tag/1.19.1-beta29#:~:text=They%20are%20published%20again%20at)).

**Removals**
- **GitHub Models.** The `langchain4j-github-models` module is removed ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=Remove%20obsolete%20langchain4j%2Dgithub%2Dmodels%20module)). Both Spring starters are removed too, and dependencies on them will fail to resolve ([Spring PR #210](https://github.com/langchain4j/langchain4j-spring/pull/210#:~:text=Applications%20that%20declare%20either%20of%20these%20dependencies%20will%20fail%20to%20resolve%20after%20this%20release)). There is no drop-in replacement because the upstream service is retired ([Spring PR #210](https://github.com/langchain4j/langchain4j-spring/pull/210#:~:text=The%20upstream%20service%20is%20retired%2C%20so%20there%20is%20no%20drop%2Din%20replacement)).
- **`JsonExtractorOutputGuardrail` is removed from `langchain4j-core`.** It had been deprecated since 1.9.0, when it moved to `langchain4j-guardrails`. Change the import and add that dependency ([PR #6184](https://github.com/langchain4j/langchain4j/pull/6184#:~:text=It%20has%20been%20deprecated%20for%20removal%20since%201.9.0%2C%20when%20the%20class%20moved%20to)).

**Behaviour and API changes from the new non-blocking support (PR #5527)**
- **Kotlin `chatAsync`.** A bare single-argument call now resolves to the Java member returning `CompletableFuture`, not the suspend extension ([PR #5527](https://github.com/langchain4j/langchain4j/pull/5527#:~:text=same%2Dsignature%20member%20wins%20over%20an%20extension)).
- **`UnsupportedFeatureException` is no longer retried.** `RetryUtils` no longer retries it ([PR #5527](https://github.com/langchain4j/langchain4j/pull/5527#:~:text=no%20longer%20retries%20it)).
- **A class can no longer implement both `ChatModel` and `StreamingChatModel`.** This is documented in the community PR, not in the 1.20.0 release notes ([community PR #776](https://github.com/langchain4j/langchain4j-community/pull/776#:~:text=A%20class%20can%20therefore%20no%20longer%20implement%20both%20interfaces)). It matters if we have custom wrappers or routers that implement both. The community `model-router` module had to be split, which is itself a breaking change to an `@Experimental` API ([community PR #776](https://github.com/langchain4j/langchain4j-community/pull/776#:~:text=technically%20a%20breaking%20change%20for%20the)).

**Jackson 3 opt-in (only if you adopt it)**
- **Exception types change.** JSON failures surface as `JsonReadException`/`JsonWriteException` instead of a `RuntimeException` wrapping Jackson's own ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=The%20one%20deliberate%20behaviour%20change%20is%20that%20a%20JSON%20failure%20surfaces%20as)).
- **A `ToolArgumentsErrorHandler` that branches on `instanceof JsonParseException` will silently take its other branch** ([PR #6184](https://github.com/langchain4j/langchain4j/pull/6184#:~:text=stops%20matching%20and%20silently%20takes%20its%20other%20branch)).
- **Four modules become lenient about unknown JSON properties:** ovh-ai, workers-ai, jlama and oracle ([PR #6184](https://github.com/langchain4j/langchain4j/pull/6184#:~:text=Four%20modules%20become%20lenient%20about%20unknown%20JSON%20properties)).
- **`OracleDocumentSplitter.split(String)` no longer declares a Jackson exception** ([PR #6184](https://github.com/langchain4j/langchain4j/pull/6184#:~:text=so%20declaring%20it%20tied%20the%20module)).
- **Jackson 2 may still arrive transitively** via vendor SDKs (AWS, Azure, Google) ([PR #6184](https://github.com/langchain4j/langchain4j/pull/6184#:~:text=Jackson%202%20still%20arrives%20transitively%20wherever%20a%20vendor%20SDK)).

**MCP deprecations (PR #6117)**
- **Jackson-typed MCP methods are deprecated, not removed.** Examples: `McpTransport.initialize`, `McpLogMessage.data()`, `McpException.errorData()` and `McpToolResultExtractor`. Replacements exist for each ([PR #6117](https://github.com/langchain4j/langchain4j/pull/6117#:~:text=deprecates%20the%20Jackson%2Dtyped%20ones)).
- **Nothing is forced yet.** The PR says nothing has to change in this release, but the deprecated methods are to be removed in a later 1.x ([PR #6117](https://github.com/langchain4j/langchain4j/pull/6117#:~:text=Nothing%20has%20to%20change%20in%20this%20release), [PR #6117](https://github.com/langchain4j/langchain4j/pull/6117#:~:text=deprecated%20methods%20are%20removed%20in%20a%20later%201.x)).
- **Three signatures are source-breaking** (including `@Internal` ones), but there are no binary or behaviour breaks ([PR #6117](https://github.com/langchain4j/langchain4j/pull/6117#:~:text=Three%20signatures%20are)).

**Provider-specific**
- **watsonx.** `embedAll(List<TextSegment>)` is no longer overridden, and the `WatsonxChatResponseMetadata` getters are renamed (e.g. `getCreated()` → `created()`) ([PR #6209](https://github.com/langchain4j/langchain4j/pull/6209#:~:text=The%20five%20getter%2Dstyle%20accessors%20were%20renamed%20to%20follow%20the%20fluent%20naming%20used%20by%20every%20other%20provider%20metadata%20class)).
- **Voyage AI.** `scoreAll` now fails fast when `topK` is smaller than the segment count, and `Builder#topK` is deprecated for removal ([PR #6180](https://github.com/langchain4j/langchain4j/pull/6180#:~:text=fails%20fast%2C%20before%20sending%20the%20request), [PR #6180](https://github.com/langchain4j/langchain4j/pull/6180#:~:text=is%20deprecated%20for%20removal)). The Voyage Spring starters still bind `top-k`, which the PR lists as a follow-up ([PR #6180](https://github.com/langchain4j/langchain4j/pull/6180#:~:text=both%20Voyage%20AI%20starters%20bind%20a)).
- **Docling.** The default parser invocation changed to async endpoints ([PR #6255](https://github.com/langchain4j/langchain4j/pull/6255#:~:text=The%20default%20invocation%20now%20targets%20the%20async%20convert%2Fchunk%20endpoints)).
- **A2A.** The interrupted-task exception is now propagated directly instead of being wrapped, so `catch` blocks that relied on the wrapper may behave differently ([PR #6038](https://github.com/langchain4j/langchain4j/pull/6038#:~:text=directly%20instead%20of%20wrapping%20it%20in%20a%20generic)).
- **OpenAI Chat Completions and Responses.** Chat Completions now throws `ContentFilteredException` on a refusal, and the Responses converter now rejects unsupported message/content types. Both are listed as "fix" entries, but they change observable behaviour ([Chat Completions refusal](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=when%20Chat%20Completions%20returns%20a%20refusal), [Responses converter](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=Reject%20unsupported%20message%20and%20content%20types%20in%20the%20Responses%20API%20converter)).
- **AI Service return types.** AI Service creation now fails fast when a LangChain4j type is used as the return type ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=fail%20fast%20when%20a%20LangChain4j%20type%20is%20used%20as%20an%20AI%20Service%20return%20type)).

# 4. What's worth trying or adopting

1. **Pin versions now.**
   - If you are on the 1.19 line, use 1.19.3 (it adds MCP backports and the ClassLoader option).
   - Otherwise take 1.20.x ([1.19.3](https://github.com/langchain4j/langchain4j/releases/tag/1.19.3#:~:text=1.19%20mcp%20backports)).
   - Reason: it avoids the faulty 1.19.1, and the 1.19.1 notice includes a "which version should I use" table ([core 1.19.1](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1#:~:text=Which%20version%20should%20I%20use%3F)).
2. **Pilot non-blocking AI Services in a non-critical service.**
   - Reason: it removes thread-per-interaction blocking. It is experimental, supports only OpenAI, Anthropic and Bedrock, and has different tool-error defaults ([PR #5527](https://github.com/langchain4j/langchain4j/pull/5527#:~:text=and%20fails%20loudly%20on%20the%20non%2Dblocking%20path%20until%20it%20opts%20in), [release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0#:~:text=A%20few%20defaults%20deliberately%20differ%20on%20the%20async%20path)).

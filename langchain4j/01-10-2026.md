# LangChain4j: what's new, Sep 2 – Oct 1, 2026

**Releases in the period**
- **Core** (langchain4j): [1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0) (Sep 4), [1.19.1](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1) (Sep 7, ⚠️ published in error), [1.19.2](https://github.com/langchain4j/langchain4j/releases/tag/1.19.2) (Sep 7), [1.19.3](https://github.com/langchain4j/langchain4j/releases/tag/1.19.3) (Sep 15), [1.20.1](https://github.com/langchain4j/langchain4j/releases/tag/1.20.1) (Sep 25), [1.20.2](https://github.com/langchain4j/langchain4j/releases/tag/1.20.2) (Sep 28). Each also has a matching `-beta29`/`-beta30` version.
- **Spring** (langchain4j-spring): the same version numbers. Only [1.20.0-beta30](https://github.com/langchain4j/langchain4j-spring/releases/tag/1.20.0-beta30) has real release notes. The others have empty notes or just a changelog link, so they look like version-alignment releases (not confirmed).
- **Community**: one release, [1.20-beta30](https://github.com/langchain4j/langchain4j-community/releases/tag/1.20-beta30) (Sep 4).

## 1. Short summary

- **1.20.0 is the main release of the month.** Everything after it is patches and backports.
- **Main theme: non-blocking AI Services.** A method can now return `CompletableFuture`, `CompletionStage` or `Flow.Publisher`. It is non-blocking end to end: tools, chat memory, guardrails and RAG. It's marked `@Experimental`.
- **Limited provider support.** Only OpenAI (Chat Completions and Responses), Anthropic and Bedrock support the new mode. Other providers fail at runtime with `AsyncNotSupportedException`, without falling back to a blocking call.
- **Second theme: getting off Jackson 2.** Jackson 3 is now an opt-in, and the MCP client's public contracts no longer use Jackson types. The Jackson-typed MCP methods are deprecated.
- **MCP got a lot of reliability fixes** in 1.20.0: timeouts, cancellation, UTF-8 in stdio, preserved error data, WebSocket and session re-init. Many were backported to 1.19.x in 1.19.2 and 1.19.3.
- **Agents and A2A:** human-in-the-loop A2A tasks can be resumed, multi-tenant routing was added, and several planner and supervisor bugs were fixed.
- **Spring** added Reactor bindings (`Mono`, `Flux<AiServiceStreamingEvent>`) and an option to run LangChain4j's background work on Spring's executor. The GitHub Models starters were removed.
- **Community** added a DynamoDB embedding store and a Xquik research tool. The `@Experimental` model-router API broke because of the core change.
- **Release incident:** 1.19.1 was published by mistake. It is not a patch; it contains all of 1.20.0. Check your dependency pins.
- **Overall:** this was a platform month (async, Jackson 3, MCP stability) rather than one with many new model integrations.

## 2. Key highlights

**Core and AI Services**
- **Non-blocking / reactive AI Services.** You pick the mode with the method's return type: `CompletableFuture<T>`, `CompletionStage<T>`, `Flow.Publisher<AiServiceStreamingEvent>` or `Flow.Publisher<String>`. The existing sync and `TokenStream` APIs are unchanged. Blocking tools run on virtual threads on Java 21+. [#5527](https://github.com/langchain4j/langchain4j/pull/5527), [docs](https://docs.langchain4j.dev/tutorials/non-blocking)
- **Opt-in Jackson 3.** Add the `langchain4j-jackson3` dependency and LangChain4j's JSON handling switches to Jackson 3, with no configuration. Some modules still need Jackson 2; the docs list them. [#6184](https://github.com/langchain4j/langchain4j/pull/6184), [docs](https://docs.langchain4j.dev/tutorials/jackson-3)

**Providers and models**
- **Gemini context caching.** The Google AI Gemini integration can now create and manage context caches. [#5725](https://github.com/langchain4j/langchain4j/pull/5725)
- **OpenAI Responses API.** Custom headers are now supported. Refusals now throw `ContentFilteredException`, and content-filtered responses map to `CONTENT_FILTER`. [#6101](https://github.com/langchain4j/langchain4j/pull/6101), [#6121](https://github.com/langchain4j/langchain4j/pull/6121), [#6182](https://github.com/langchain4j/langchain4j/pull/6182)
- **Bedrock:** the Converse APIs now accept request metadata. [#6189](https://github.com/langchain4j/langchain4j/pull/6189)
- **watsonx:** new Gateway models, cancellation of streaming, and inline chat moderation. [#6209](https://github.com/langchain4j/langchain4j/pull/6209)

**MCP**
- **Jackson-free MCP contracts.** New methods replace the Jackson-typed ones: `sendRequest`/`sendMessage`, `dataAsMap`/`dataAsJson`, `errorDataAsMap`, and `McpToolResultConverter`. Tool-call arguments are now `Map<String, Object>`. This also fixes a bug where tool arguments were silently serialized wrong under a Jackson 3 mapper. [#6117](https://github.com/langchain4j/langchain4j/pull/6117)
- **Reliability fixes.** Pending operations are cancelled and the server notified on timeouts; JSON-RPC errors now surface instead of NPEs; stdio and Docker use UTF-8; WebSocket send failures propagate; error data is kept in `McpException`. See the [1.20.0 notes](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0). Some of these were backported to 1.19.x in [#6329](https://github.com/langchain4j/langchain4j/pull/6329) and [#6412](https://github.com/langchain4j/langchain4j/pull/6412).
- **`@McpClientSupplier` methods can take parameters** (1.20.1), resolved through `SupplierParameterResolver`. [#6505](https://github.com/langchain4j/langchain4j/pull/6505)

**Agents and A2A**
- **Human-in-the-loop A2A tasks can be resumed.** [#6038](https://github.com/langchain4j/langchain4j/pull/6038)
- **Multi-tenant A2A.** 1.20.0 added the `@A2ATenantId` annotation. 1.20.2 added automatic tenant resolution from the agent card, plus `@A2AClientAgent.tenant()` and `A2AClientBuilder.tenant()`. It also fixed a `StackOverflowError` from circular `toString` in `DefaultAgenticScope`. [#6303](https://github.com/langchain4j/langchain4j/pull/6303), [#6512](https://github.com/langchain4j/langchain4j/pull/6512)
- **Agent fixes:** the P2P planner now stops at a stable state and respects `maxAgentsInvocations`; agent argument descriptions are kept; the original exception from agents is propagated. A ClassLoader can now be set for AgenticScope serialization (backported to 1.19.3). [#5894](https://github.com/langchain4j/langchain4j/pull/5894), [#5898](https://github.com/langchain4j/langchain4j/pull/5898), [#6207](https://github.com/langchain4j/langchain4j/pull/6207)

**RAG and document parsing**
- **Docling parser:** DocumentRequest templates, async parsing and a custom request executor. [#6255](https://github.com/langchain4j/langchain4j/pull/6255)
- **Azure AI Search:** fields from your own (pre-existing) index are now exposed as metadata. [#6022](https://github.com/langchain4j/langchain4j/pull/6022)
- **Embedding store correctness fixes** that may change results for existing stores:
  - Chroma relevance scores are fixed for collections that don't use cosine distance ([#6077](https://github.com/langchain4j/langchain4j/pull/6077)).
  - Azure Cosmos DB NoSQL filtered search was missing its WHERE clause ([#5921](https://github.com/langchain4j/langchain4j/pull/5921)).
  - `ReRankingContentAggregator` now keeps content metadata ([#6129](https://github.com/langchain4j/langchain4j/pull/6129)).
  - Milvus lookups now work for IDs with special characters ([#6088](https://github.com/langchain4j/langchain4j/pull/6088)).

**Spring starters**
- **Reactor bindings and Spring executor.** `Mono<T>` (also allowed as a `@Tool` return type) and `Flux<AiServiceStreamingEvent>` now work with the non-blocking mode. A new property, `langchain4j.executor.use-spring-task-executor=true`, sends background work through Spring's `AsyncTaskExecutor`, so MDC, tracing and security context are carried over. It is off by default. [spring#211](https://github.com/langchain4j/langchain4j-spring/pull/211)
- **Starter property fixes.** Every property of the OpenAI and Anthropic starters is now tested, and the bugs found were fixed. [spring#206](https://github.com/langchain4j/langchain4j-spring/pull/206), [spring#207](https://github.com/langchain4j/langchain4j-spring/pull/207)

**Community**
- **New integrations:** an Amazon DynamoDB embedding store ([#755](https://github.com/langchain4j/langchain4j-community/pull/755)) and a Xquik research tool ([#753](https://github.com/langchain4j/langchain4j-community/pull/753)).
- **Other additions:** DashScope supports qwen3.8-max and qwen-image-3.0 ([#749](https://github.com/langchain4j/langchain4j-community/pull/749)), and Cohere has a `TokenCountEstimator` ([#748](https://github.com/langchain4j/langchain4j-community/pull/748)).

## 3. Breaking changes and deprecations

1. **⚠️ 1.19.1 was published by mistake.** It contains all of 1.20.0 plus later commits (108 commits ahead of 1.19.0). If you're on 1.19.1, go to 1.20.x, not 1.19.2, or you will silently lose features. To stay on the 1.19 line, use 1.19.3. Tools that pick "the newest release below X" as an API baseline (for example revapi) will choose 1.19.1 and report misleading differences. This applies to Spring 1.19.1-beta29 too. [Release note](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1)
2. **`StreamingChatModel` changed in 1.20.0.** It now declares `doChat(ChatRequest)` returning `Flow.Publisher<…>`, which clashes with `ChatModel.doChat`. **One class can no longer implement both `ChatModel` and `StreamingChatModel`.** ⚠️ The core release notes and #5527 don't list this as a breaking change; it comes from community [PR #776](https://github.com/langchain4j/langchain4j-community/pull/776), where it broke the build. Check any custom model wrappers or decorators you have.
3. **Changes in #5527** ([link](https://github.com/langchain4j/langchain4j/pull/5527)):
   - In Kotlin, `model.chatAsync(request)` now resolves to the Java method returning `CompletableFuture`, not the `suspend` extension. Use `.await()` or pass a coroutine context.
   - `UnsupportedFeatureException` is now a `NonRetriableException`, so `RetryUtils` no longer retries it.
   - On the async path, tool error handling is reversed and multiple tool calls run concurrently. `@Moderate` is rejected when the AI Service is created.
4. **GitHub Models removed:** the `langchain4j-github-models` module ([#5692](https://github.com/langchain4j/langchain4j/pull/5692)) and its Spring Boot starters ([spring#210](https://github.com/langchain4j/langchain4j-spring/pull/210)). The release notes don't say what to migrate to. My guess is an OpenAI-compatible client, but that isn't confirmed.
5. **MCP ([#6117](https://github.com/langchain4j/langchain4j/pull/6117)):**
   - **Deprecated:** `McpLogMessage.data()`, `McpException.errorData()`, `toolResultExtractor`/`McpToolResultExtractor`, `McpMeta.getPublisherProvided()`, and the Jackson-typed `McpTransport` and `McpOperationHandler` methods. They are planned for removal "in a later 1.x".
   - **Source-breaking:** `McpCallToolRequest` and `McpCallToolParams` arguments changed from `ObjectNode` to `Map`.
   - **Trap for custom transports:** the deprecated methods throw instead of delegating to the new ones. Migrate your transport's own internal calls too.
   - This PR was also backported into 1.19.2.
6. **Jackson 3 opt-in:** JSON errors become `JsonReadException`/`JsonWriteException` instead of a wrapped Jackson exception. Catching `RuntimeException` still works.
7. **Voyage AI:** `topK` in the scoring model is deprecated, and it now returns one score per segment. [#6180](https://github.com/langchain4j/langchain4j/pull/6180)
8. **Community model-router (`@Experimental`):** it's split into sync and streaming versions. Adding streaming routes now goes through `StreamingModelRouter`, and `ModelRoutingStrategy.route` takes `List<? extends ModelWrapper>`. [#776](https://github.com/langchain4j/langchain4j-community/pull/776)
9. **Behaviour changes worth checking:**
   - A LangChain4j type used as an AI Service return type now fails immediately ([#6187](https://github.com/langchain4j/langchain4j/pull/6187)).
   - Malformed JSON objects now throw `OutputParsingException` ([#6110](https://github.com/langchain4j/langchain4j/pull/6110)).
   - Chat Completions refusals now throw `ContentFilteredException` ([#6114](https://github.com/langchain4j/langchain4j/pull/6114)).

## 4. Worth trying or adopting

- **Upgrade to 1.20.2.** It's the current patch and includes the MCP reliability fixes and the A2A tenant and `StackOverflowError` fixes. Check items 1–2 and 4 from section 3 first.
- **Non-blocking AI Services (only on OpenAI, Anthropic or Bedrock).** Worth trying for high-concurrency services or WebFlux; on Spring, use `Mono`/`Flux` from `langchain4j-reactor`. Since it's experimental and the tool-error defaults differ, roll it out gradually.
- **`langchain4j.executor.use-spring-task-executor=true`** if you use the async mode. Otherwise MDC, tracing and security context won't follow the async hops.
- **Move to the new MCP APIs now** (`dataAsMap`, `errorDataAsMap`, `toolResultConverter`, new transport methods). That avoids a forced migration when the deprecated methods are removed.
- **Jackson 3 opt-in** if you're moving to Spring Boot 4 or Jackson 3 in general. Check which modules you use still need Jackson 2 (listed in the docs).
- **Gemini context caching** if you use Gemini with long, repeated contexts, to save tokens.
- **A2A multi-tenancy and resuming HITL tasks** if you're building multi-agent A2A setups.
- **Re-check RAG quality** if you use Chroma (non-cosine distance), Azure Cosmos DB NoSQL with filters, or the re-ranking aggregator. The fixes change results.

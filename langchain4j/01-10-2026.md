## 1. Short summary

- **Main story:** 1.20.0 is the big release of the period. It adds experimental non-blocking and reactive AI Services, where a method can return `CompletableFuture` or `Flow.Publisher` ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0), [PR #5527](https://github.com/langchain4j/langchain4j/pull/5527)).
- **Spring follow-through:** The Spring repo shipped the Reactor bindings (`Mono`, `Flux`) and an opt-in switch to use Spring's task executor the same day ([release](https://github.com/langchain4j/langchain4j-spring/releases/tag/1.20.0-beta30), [PR #211](https://github.com/langchain4j/langchain4j-spring/pull/211)).
- **Jackson 3:** 1.20.0 also adds opt-in Jackson 3 support. You add `langchain4j-jackson3` to the classpath, and nothing changes for anyone who doesn't ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0), [PR #6184](https://github.com/langchain4j/langchain4j/pull/6184)).
- **MCP:** MCP got heavy attention. Many robustness fixes landed (timeouts, cancellation, UTF-8, error propagation), listed in the [1.20.0 notes](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0). Jackson types were also deprecated in the MCP public API ([PR #6117](https://github.com/langchain4j/langchain4j/pull/6117)).
- **Agentic/A2A:** This area saw incremental work. A2A human-in-the-loop resume ([PR #6038](https://github.com/langchain4j/langchain4j/pull/6038)) and a multi-tenant `@A2ATenantId` ([PR #6303](https://github.com/langchain4j/langchain4j/pull/6303)) both shipped in 1.20.0.
- **Provider and RAG additions:**
  - Gemini context-cache management ([PR #5725](https://github.com/langchain4j/langchain4j/pull/5725)).
  - A bigger watsonx module update ([PR #6209](https://github.com/langchain4j/langchain4j/pull/6209)).
  - Docling parser enhancements ([PR #6255](https://github.com/langchain4j/langchain4j/pull/6255)).
  - A community Amazon DynamoDB embedding store ([PR #755](https://github.com/langchain4j/langchain4j-community/pull/755)).
- **Clean-up:** The retired GitHub Models integration was removed from both core ([PR #5692](https://github.com/langchain4j/langchain4j/pull/5692)) and Spring ([PR #210](https://github.com/langchain4j/langchain4j-spring/pull/210)).
- **Release hygiene incident:** 1.19.1 was cut from `main` by mistake and contains all of 1.20.0 plus later commits. Maven Central can't withdraw it ([release 1.19.1](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1)).
- **Patch cadence:** After 1.20.0, the 1.19.x line only received MCP backports ([1.19.2](https://github.com/langchain4j/langchain4j/releases/tag/1.19.2), [1.19.3](https://github.com/langchain4j/langchain4j/releases/tag/1.19.3)). 1.20.1 and 1.20.2 are tiny patches ([1.20.1](https://github.com/langchain4j/langchain4j/releases/tag/1.20.1), [1.20.2](https://github.com/langchain4j/langchain4j/releases/tag/1.20.2)).

## 2. Key highlights

### Core (langchain4j)

- **Non-blocking / reactive AI Services (`@Experimental`, since 1.20.0).**
  - You pick the mode by return type: `CompletableFuture<T>` / `CompletionStage<T>` for one response, `Flow.Publisher<AiServiceStreamingEvent>` / `Flow.Publisher<String>` for streaming. Non-blocking is carried through tools, chat memory, guardrails and the RAG retrieval graph ([release 1.20.0](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0), [PR #5527](https://github.com/langchain4j/langchain4j/pull/5527)).
  - **Provider support is narrow.** Only OpenAI (Chat Completions and Responses), Anthropic and Bedrock support it today. Any other provider compiles, then fails at runtime with `AsyncNotSupportedException` ([docs @1.20.0](https://github.com/langchain4j/langchain4j/blob/1.20.0/docs/docs/tutorials/non-blocking.md)).
  - **Context propagation:** MDC, tracing and security context are not propagated across threads automatically. You supply a context-propagating executor through the `ExecutorProvider` SPI ([docs](https://github.com/langchain4j/langchain4j/blob/1.20.0/docs/docs/tutorials/non-blocking.md)).
- **Jackson 3 opt-in (`langchain4j-jackson3`).**
  - Jackson 3 is a single dependency with no configuration. Existing chat-memory and `InMemoryEmbeddingStore` data written by Jackson 2 stays readable ([docs @1.20.0](https://github.com/langchain4j/langchain4j/blob/1.20.0/docs/docs/tutorials/jackson-3.md), [PR #6184](https://github.com/langchain4j/langchain4j/pull/6184)).
  - Jackson 2 can't be fully excluded if you use `langchain4j-mcp`, `langchain4j-guardrails`, `langchain4j-vespa` or cloud vendor SDKs ([docs](https://github.com/langchain4j/langchain4j/blob/1.20.0/docs/docs/tutorials/jackson-3.md)).
- **MCP client.**
  - Jackson types were removed from the MCP contracts. Jackson-free alternatives were added and the old methods deprecated, not removed ([PR #6117](https://github.com/langchain4j/langchain4j/pull/6117)).
  - Many fixes landed: cancel-on-timeout, `McpException` preserving JSON-RPC error data, UTF-8 for stdio/Docker, and failing fast on a repeated 404 after session reinitialization. These are listed in the [1.20.0 notes](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0). I only read the titles, not the individual PRs.
  - Selected MCP fixes were backported to 1.19.x ([PR #6329](https://github.com/langchain4j/langchain4j/pull/6329), [1.19.3 notes](https://github.com/langchain4j/langchain4j/releases/tag/1.19.3)).
- **Agentic / A2A.**
  - **Human-in-the-loop resume:** A2A tasks paused with `input-required` or `auth-required` can now be resumed. `A2ATaskInterruptedException` carries `contextId` and `taskId`, which you pass back via `@A2AContextId` and `@A2ATaskId` ([PR #6038](https://github.com/langchain4j/langchain4j/pull/6038)).
  - **Multi-tenant routing:** `@A2ATenantId` adds per-call tenant routing, and the A2A SDK moves from 1.1.0 to 1.3.1 ([PR #6303](https://github.com/langchain4j/langchain4j/pull/6303)).
  - **Serialization:** The `ObjectMapper` used for `AgenticScope` serialization can now take a custom `ClassLoader` ([1.20.0 notes](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0), also in [1.19.3](https://github.com/langchain4j/langchain4j/releases/tag/1.19.3)).
  - **Declarative MCP agents:** `@McpClientSupplier` methods may now take parameters resolved by `SupplierParameterResolver`s. Previously the agent failed to build ([PR #6505](https://github.com/langchain4j/langchain4j/pull/6505), [1.20.1](https://github.com/langchain4j/langchain4j/releases/tag/1.20.1)).
  - **Agent descriptions:** Agent argument descriptions are now preserved ([1.20.0 notes, #6241](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0)). I didn't read the PR.
- **Gemini context caching.** `GeminiCaches` adds `createCache` / `getCache` / `listCaches` / `deleteCache` to `langchain4j-google-ai-gemini`. Updating a cache's TTL is not included ([PR #5725](https://github.com/langchain4j/langchain4j/pull/5725)).
- **watsonx module.** It gained streaming cancellation, embedding listeners, new Model Gateway embedding and image models, and inline chat moderation ([PR #6209](https://github.com/langchain4j/langchain4j/pull/6209)).
- **Docling document parser.** It adds `DocumentRequest` templates, `parseAsync` returning `CompletionStage<Document>`, and a pluggable `DoclingRequestExecutor` ([PR #6255](https://github.com/langchain4j/langchain4j/pull/6255)).
- **Smaller provider additions** (release-note titles only, PRs not read):
  - Bedrock Converse request metadata ([#6189](https://github.com/langchain4j/langchain4j/pull/6189)).
  - `customHeaders` for the OpenAI Responses API ([#6101](https://github.com/langchain4j/langchain4j/pull/6101)).
  - Jina per-call `INPUT_TYPE` ([#6165](https://github.com/langchain4j/langchain4j/pull/6165)).
  - Azure AI Search bring-your-own index fields exposed as metadata ([#6022](https://github.com/langchain4j/langchain4j/pull/6022)).
- **Embedding-store correctness fixes.** The following fixes are worth a look if you use these stores. I judged them from titles only:
  - Azure Cosmos DB NoSQL: missing `WHERE` clause in filtered vector search ([#5921](https://github.com/langchain4j/langchain4j/pull/5921)).
  - Azure AI Search: metadata filter quote escaping ([#5900](https://github.com/langchain4j/langchain4j/pull/5900)).
  - Chroma: invalid relevance scores for non-cosine collections ([#6077](https://github.com/langchain4j/langchain4j/pull/6077)).
  - Milvus: lookups for IDs with special characters ([#6088](https://github.com/langchain4j/langchain4j/pull/6088)).

### Spring (langchain4j-spring)

- **Reactor bindings for the non-blocking modes.**
  - `Mono<T>` and `Flux<AiServiceStreamingEvent>` are supported in `langchain4j-reactor` ([PR #211](https://github.com/langchain4j/langchain4j-spring/pull/211)).
  - `Flux<String>` deliberately stays on the old `TokenStream` adapter, so existing code doesn't move to the non-blocking path ([PR #211](https://github.com/langchain4j/langchain4j-spring/pull/211)).
  - Mutiny `Uni`/`Multi` are not supported yet ([docs](https://github.com/langchain4j/langchain4j/blob/1.20.0/docs/docs/tutorials/non-blocking.md)).
- **Spring executor for offloaded work.** Setting `langchain4j.executor.use-spring-task-executor=true` routes blocking tools, offloaded retrieval and retry backoff through Spring's executor. This lets a `TaskDecorator` propagate MDC, tracing and security context. It is off by default ([PR #211](https://github.com/langchain4j/langchain4j-spring/pull/211)).
- **Starter test overhaul** ([PR #204](https://github.com/langchain4j/langchain4j-spring/pull/204)).
  - Tests now use WireMock-stubbed providers and check that configured properties reach the wire.
  - Follow-up PRs claim to "fix what that uncovered" in the OpenAI and Anthropic starters ([#206](https://github.com/langchain4j/langchain4j-spring/pull/206), [#207](https://github.com/langchain4j/langchain4j-spring/pull/207)). The release notes don't say which property bugs were fixed (see §5).
  - It also adds a missing `langchain4j.google-ai-gemini.embedding-model.base-url` property ([PR #204](https://github.com/langchain4j/langchain4j-spring/pull/204)).

### Community (langchain4j-community 1.20-beta30)

- **Amazon DynamoDB embedding store** (`langchain4j-community-dynamodb`).
  - It uses DynamoDB native vector search with COSINE, EUCLIDEAN and DOT_PRODUCT distances.
  - Metadata filtering is equality-only (`IsEqualTo`, optionally combined with `And`), and `removeAll(Filter)` is unsupported ([PR #755](https://github.com/langchain4j/langchain4j-community/pull/755)).
- **Xquik research tool** ([PR #753](https://github.com/langchain4j/langchain4j-community/pull/753)).
- **Cohere `TokenCountEstimator`** ([PR #748](https://github.com/langchain4j/langchain4j-community/pull/748)).
- **DashScope: qwen3.8-max and qwen-image-3.0** ([PR #749](https://github.com/langchain4j/langchain4j-community/pull/749)).

## 3. Breaking changes, deprecations, risks

**A. Do not use 1.19.1 / 1.19.1-beta29.**
- Core 1.19.1 and Spring 1.19.1-beta29 were published in error.
- If you are on 1.19.1, go to 1.20.0 or later, **not** to 1.19.2. 1.19.2 contains less code and would silently drop about 108 commits.
- Source: [1.19.1 release](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1).
- Tools that pick "the newest release below X" as a baseline (for example revapi `RELEASE`) will select 1.19.1 and give misleading results. Source: [same release](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1).

**B. Core API changes from the non-blocking PR.** Source for all of B: [PR #5527](https://github.com/langchain4j/langchain4j/pull/5527), unless noted.
- **`UnsupportedFeatureException` is now a `NonRetriableException`.** `RetryUtils` no longer retries it. If you relied on those retries, retry explicitly.
- **Kotlin:** `ChatModel` now has a Java member `chatAsync(ChatRequest)`. A bare single-argument `model.chatAsync(request)` now resolves to it and returns a `CompletableFuture`, not the old suspend extension. Fix it with `.await()` or by passing a `coroutineContext`.
- **A class can no longer implement both `ChatModel` and `StreamingChatModel`.** `StreamingChatModel` now declares a `doChat(ChatRequest)` returning `Flow.Publisher<ChatModelStreamingEvent>`, which conflicts with `ChatModel.doChat`. This was found through the community module ([community PR #776](https://github.com/langchain4j/langchain4j-community/pull/776)). The core PR's breaking-changes section does not list it, so check your own custom model classes.
- **Defaults differ on the async path** (opt-in by return type only):
  - Tools run concurrently.
  - A tool execution error fails the invocation, while an argument-parse error goes back to the LLM.
  - `@Moderate` is rejected ([docs](https://github.com/langchain4j/langchain4j/blob/1.20.0/docs/docs/tutorials/non-blocking.md)).

**C. MCP deprecations ([PR #6117](https://github.com/langchain4j/langchain4j/pull/6117)).**
- **Deprecated, still working:**
  - `McpLogMessage.data()`: use `dataAsMap()` / `dataAsJson()`.
  - `McpException.errorData()`: use `errorDataAsMap()` / `errorDataAsJson()`.
  - `toolResultExtractor`: use `toolResultConverter`.
  - `McpMeta.getPublisherProvided()`: use `publisherProvided()`.
  - The `McpTransport` / `McpOperationHandler` methods: new names are `sendInitializeRequest`, `sendRequest`, `sendMessage`, `onMessage` and `expectResponse`.
- **Three source-breaking signature changes** (the PR leaves its own "no breaking changes" box unticked):
  - `McpCallToolRequest` arguments move from `ObjectNode` to `Map<String,Object>` (`@Internal`).
  - The `JsonRpcIoHandler` consumer becomes `Consumer<String>`.
  - The `McpOperationHandler` constructor changes. The class is public and not `@Internal`.
- **Custom `McpTransport` implementers:** the deprecated methods now throw rather than delegate to the new ones, so internal calls that still compile can fail at runtime ([PR #6117](https://github.com/langchain4j/langchain4j/pull/6117)).
- **Backport:** the PR was also backported to 1.19.2, described by its author as "a bit questionable" ([PR #6329](https://github.com/langchain4j/langchain4j/pull/6329)).

**D. GitHub Models removed.**
- The `langchain4j-github-models` module is removed ([PR #5692](https://github.com/langchain4j/langchain4j/pull/5692)).
- Both `langchain4j-github-models-spring-boot-starter` and `...-spring-boot4-starter` are removed. The `langchain4j.github-models.*` properties are no longer recognised ([Spring PR #210](https://github.com/langchain4j/langchain4j-spring/pull/210)).
- The PRs cite a GitHub changelog saying the service was fully retired on July 30, 2026. I did not open that changelog myself. Migrate to another provider ([Spring PR #210](https://github.com/langchain4j/langchain4j-spring/pull/210)).

**E. Jackson 3 opt-in changes exceptions.** Only if you add the module ([docs @1.20.0](https://github.com/langchain4j/langchain4j/blob/1.20.0/docs/docs/tutorials/jackson-3.md)):
- JSON failures become `JsonReadException` / `JsonWriteException` instead of a wrapped Jackson exception.
- A `toolArgumentsErrorHandler` that does `instanceof JsonParseException` silently stops matching.
- The root cause under `OutputParsingException` changes.

**F. Voyage AI reranker ([PR #6180](https://github.com/langchain4j/langchain4j/pull/6180)).**
- `VoyageAiScoringModel.Builder#topK` is deprecated for removal.
- `scoreAll` now throws `IllegalArgumentException` if `topK` is less than the number of segments. Use `ReRankingContentAggregator.maxResults(...)` instead.
- The PR notes that the Voyage AI Spring starters still bind `top-k` and call the deprecated method, as a follow-up. I did not verify whether that follow-up shipped.

**G. Beta and experimental modules.**
- **watsonx** ([PR #6209](https://github.com/langchain4j/langchain4j/pull/6209)):
  - `WatsonxEmbeddingModel.embedAll` override removed.
  - `WatsonxChatResponseMetadata` getters renamed (`getCreated()` → `created()`, and four more).
  - The SDK type `ModelGatewayParameters` is renamed `ModelGatewayChatParameters`.
- **Community `model-router`** (`@Experimental`): `ModelRouter` and `ChatModelWrapper` are now `ChatModel`-only. New `StreamingModelRouter` and `StreamingChatModelWrapper` classes take over streaming ([community PR #776](https://github.com/langchain4j/langchain4j-community/pull/776)).
- **Spring Gemini starter:** `EmbeddingModelProperties` (Boot 3) and `GoogleAiGeminiEmbeddingModelProperties` (Boot 4) gained a `baseUrl` record component. This only breaks code that constructs them directly ([Spring PR #204](https://github.com/langchain4j/langchain4j-spring/pull/204)).

**H. Behaviour changes from "fix" items.** I read only the release-note titles, so check the PRs before upgrading:
- `ContentFilteredException` is now thrown when Chat Completions returns a refusal ([#6114](https://github.com/langchain4j/langchain4j/pull/6114)) and when the Responses API does ([#6121](https://github.com/langchain4j/langchain4j/pull/6121)).
- Using a LangChain4j type as an AI Service return type now fails fast ([#6187](https://github.com/langchain4j/langchain4j/pull/6187)).
- Internal agent methods now propagate the original exception ([#5982](https://github.com/langchain4j/langchain4j/pull/5982)).

**I. Docling default endpoint changed.**
- The default invocation now calls Docling's async convert/chunk endpoints instead of the synchronous one. The PR labels this an "Endpoint/behaviour change" but ticks "no breaking changes" ([PR #6255](https://github.com/langchain4j/langchain4j/pull/6255)).
- Check it against your Docling Serve version.

## 4. What's worth trying or adopting

1. **Move to 1.20.2** (or 1.19.3 if you must stay on 1.19.x), and skip 1.19.1. 1.20.2 is the latest core and Spring release in the period ([1.20.2](https://github.com/langchain4j/langchain4j/releases/tag/1.20.2)). The warning in [1.19.1](https://github.com/langchain4j/langchain4j/releases/tag/1.19.1) explains why.
2. **Pilot non-blocking AI Services, if you're on a reactive stack** and use OpenAI, Anthropic or Bedrock. A single thread can drive many concurrent interactions ([PR #5527](https://github.com/langchain4j/langchain4j/pull/5527)). It is experimental, and the provider list is short ([docs](https://github.com/langchain4j/langchain4j/blob/1.20.0/docs/docs/tutorials/non-blocking.md)). Plan for context propagation first.
3. **On Spring, set `langchain4j.executor.use-spring-task-executor=true`** if you use async modes. It keeps tracing, MDC and security context across threads ([PR #211](https://github.com/langchain4j/langchain4j-spring/pull/211)).
4. **Start moving off the deprecated MCP Jackson APIs** now, especially custom transports, `McpLogMessage.data()`, `McpException.errorData()` and `toolResultExtractor`. The mapping table is in [PR #6117](https://github.com/langchain4j/langchain4j/pull/6117).
5. **Try the Jackson 3 opt-in in a test environment**, if you are heading to Jackson 3. Before you do, audit any `JsonParseException` handlers ([docs](https://github.com/langchain4j/langchain4j/blob/1.20.0/docs/docs/tutorials/jackson-3.md)).
6. **If you use A2A or agentic features:** look at HITL resume ([PR #6038](https://github.com/langchain4j/langchain4j/pull/6038)) and `@A2ATenantId` ([PR #6303](https://github.com/langchain4j/langchain4j/pull/6303)).
7. **If you use Gemini with large repeated prompts:** `GeminiCaches` removes the need to create caches outside LangChain4j ([PR #5725](https://github.com/langchain4j/langchain4j/pull/5725)). Context caching needs a paid-tier key, since the PR's integration test skips on the free tier.
8. **If you are on AWS and need low-latency vector search:** evaluate the community DynamoDB store. The PR positions it against S3 Vectors, which it recommends for infrequent queries. Only equality filters are supported ([PR #755](https://github.com/langchain4j/langchain4j-community/pull/755)).
9. **If you use Azure Cosmos DB, Azure AI Search, Chroma or Milvus stores:** read the correctness fixes listed in §2 and confirm they cover your usage.

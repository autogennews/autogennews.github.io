## 🚀 What Actually Mattered

### 1. Rate Limits: Permanent +25%, But Actually a 17% Cut From Today
**What it does:** Starting **September 14**, Anthropic permanently raises standard weekly Claude Code limits by **25% over the original baseline** for Pro, Max, Team, and seat-based Enterprise plans. The current temporary **50% boost** (in place since ~May) ends the same day.

**Why it matters:** If you've been enjoying the 50% promo, you're losing capacity. The math: 125% of baseline replaces 150% of baseline = a **net 17% reduction** from what you have right now. Anthropic framed it as a raise; the community immediately did the math and called it a cut. This was the most-discussed Claude Code topic of the week.

**Verification:** ✅ Official — announced by [@ClaudeDevs](https://x.com/ClaudeDevs/status/2093742321473065266) on Aug 29.

**Sources:** [ClaudeDevs on X](https://x.com/ClaudeDevs/status/2093742321473065266), [Android Headlines](https://www.androidheadlines.com/2026/08/anthropic-claude-code-weekly-limits-update.html), [MacObserver](https://www.macobserver.com/news/anthropic-raises-claude-code-weekly-limits-by-25-for-paid-plans/), [Reddit r/AI_Agents](https://www.reddit.com/r/AI_Agents/comments/1w1smho/claude_code_reducing_rate_limit_by_25_starting/)

### 2. `--restricted` Mode (v2.1.248)
**What it does:** New `--restricted` flag (or `CLAUDE_CODE_RESTRICTED=1`) strips out built-in command/code execution tools and `WebFetch` (unless explicitly included via `--tools`), locks file tools to the working directory, refuses `bypassPermissions`, and ignores user/project/local settings files.

**Why it matters:** This is the hardened mode for embedding Claude Code in pipelines, CI, or anywhere you need a locked-down agent that can only read/write files in scope. Previously you had to cobble this together with permission rules; now it's a single flag.

**Verification:** ✅ Official — [GitHub releases](https://github.com/anthropics/claude-code/releases), [ClaudeCodeLog](https://x.com/ClaudeCodeLog/status/2093104161684369626)

### 3. `PreModelSwitch` / `PostModelSwitch` Hooks (v2.1.251)
**What it does:** New hook events let you **block, confirm, or annotate** model switches. `SessionStart` resume hooks now also receive session staleness and estimated prompt-cache rewarm cost.

**Why it matters:** For teams managing model governance (e.g., preventing accidental switches to expensive models, or logging which model ran which task), this is the missing piece. Combined with the cache-rewarm cost data, you can now make informed decisions about whether to resume a stale session or start fresh.

**Verification:** ✅ Official — [GitHub releases](https://github.com/anthropics/claude-code/releases), [ClaudeCodeLog](https://x.com/ClaudeCodeLog/status/2093407907446444049)

### 4. Linux Binary: 340 MB → ~75 MB, 40–70 MB Less RAM Per Session (v2.1.243)
**What it does:** Linux x64 install size dropped by **~4.5×**. Per-session memory usage dropped by **40–70 MB**.

**Why it matters:** Meaningful for anyone running Claude Code on remote servers, containers, or resource-constrained dev machines. Faster installs, less overhead when running multiple sessions.

**Verification:** ✅ Official — [changelog](https://claudebeat.ai/articles/2026/08/2026-08-25.html), [Qiita summary](https://qiita.com/moha0918_/items/f430ec14a58612a484a7)

### 5. Prompt Cache TTL Controls (v2.1.243) + Per-Agent `experimental.cacheTtl` (v2.1.248)
**What it does:** Two new settings — `promptCacheTtl` and `subagentPromptCacheTtl` — let API-key and cloud-provider users set **1-hour cache** on the main conversation while keeping subagents at **5 minutes** (or vice versa). v2.1.248 added per-agent `experimental.cacheTtl` in frontmatter for even finer control.

**Why it matters:** Long agentic sessions with API keys previously suffered frequent cache misses. You can now keep the main conversation cached for an hour, significantly reducing token costs on extended coding sessions. The per-agent frontmatter override in v2.1.248 gives skill/agent authors control without touching global settings.

**Verification:** ✅ Official — [changelog](https://claudebeat.ai/articles/2026/08/2026-08-25.html), [getclaudeskills.com](https://www.getclaudeskills.com/blog/claude-code-prompt-cache-ttl-settings)

### 6. `/permissions` Auto Mode Tab (v2.1.246)
**What it does:** You can now **view and edit auto mode classifier rules** directly from `/permissions` instead of manually editing `~/.claude/settings.json`. Also added a startup warning for Bash allow rules with wildcards before the subcommand (e.g., `Bash(git * main)`).

**Why it matters:** Auto mode became the default on Aug 14. This makes the rules governing what auto-approves actually visible and editable in-session — critical for understanding what Claude is doing without asking you. The wildcard warning catches a real footgun where `git * main` would also match `git --force push main`.

**Verification:** ✅ Official — [ClaudeDevs](https://x.com/ClaudeDevs/status/2093480630801858750), [claudeupdates.dev](https://www.claudeupdates.dev/version/2.1.246)

### 7. Shopify CEO Threatens to Ban Claude Code Over AGENTS.md
**What it does:** Tobi Lütke publicly said he's **considering banning Claude Code at Shopify** because it only reads `CLAUDE.md` while Codex, Cursor, and other tools have standardized on `AGENTS.md` and `.agents/skills`. He called it a "complexity tax" for multi-tool teams.

**Why it matters:** This is the highest-profile public pressure on Anthropic to support vendor-neutral agent config. The workaround today is importing `@AGENTS.md` from `CLAUDE.md`, but that's a band-aid. No official ship date for native AGENTS.md support has been announced.

**Verification:** ⚠️ Mixed — Lütke's post is confirmed (63K+ views on X). Anthropic has reportedly acknowledged the issue but no concrete timeline. **Sources:** [The New Stack on X](https://x.com/thenewstack/status/2092356604708388879), [explainx.ai](https://explainx.ai/blog/tobi-shopify-claude-code-agents-md-ban-threat-august-2026), [36kr](https://eu.36kr.com/en/p/3955873528626311)

### 8. Auto Mode Security Bypass Demonstrated
**What it does:** Security researcher Johann Rehberger (Embrace The Red) demonstrated that Claude Code's auto mode safety classifier can be **bypassed via prompt injection**, allowing unauthorized actions to execute without human approval.

**Why it matters:** Auto mode is now the default. Anthropic's position is that auto mode is a "convenience feature backed by a best-effort classifier, not a security guarantee." If you're running Claude Code on sensitive codebases or with untrusted inputs, this is worth understanding. Consider `--restricted` mode or manual mode for high-risk scenarios.

**Verification:** ⚠️ Mixed — security research is published ([Embrace The Red](https://embracethered.com/blog/posts/2026/breaking-claude-code-opus-5-and-automode/)), Anthropic's response is documented but they haven't disputed the findings.

## 🔧 Useful Tips & Tricks

**Cache cost savings for API users:** Set `"promptCacheTtl": "1h"` in your settings to keep the main conversation cached for an hour. Leave `"subagentPromptCacheTtl": "5m"` at default unless you have long-running subagent tasks. Precedence: `FORCE_PROMPT_CACHING_5M=1` > env var > setting > `ENABLE_PROMPT_CACHING_1H=1` > default.
*Source: [getclaudeskills.com](https://www.getclaudeskills.com/blog/claude-code-prompt-cache-ttl-settings), [claudehub.fr](https://www.claudehub.fr/blog/claude-code-2-1-243-245-cache-une-heure-reglable/) — ✅ Official*

**Use `/usage` loop breakdowns to catch runaway loops:** The new per-loop table shows run count, total tokens, tokens per run, and last-run timestamp. If a `/loop` task is burning tokens, you'll see it immediately.
*Source: [changelog](https://claudebeat.ai/articles/2026/08/2026-08-25.html) — ✅ Official*

**`modelPicker` for team standardization:** Customize which models appear in `/model` with custom ordering and labels. Note: this setting is ignored in project/local settings — it's read from managed/user-level config only.
*Source: [claudehub.fr](https://www.claudehub.fr/blog/claude-code-2-1-243-245-cache-une-heure-reglable/) — ✅ Official*

**AGENTS.md workaround:** If your team uses multiple AI coding tools, add `@AGENTS.md` as an import in your `CLAUDE.md` to share a single source of truth. Not native support, but functional.
*Source: [community-reported](https://eu.36kr.com/en/p/3955873528626311) — ⚠️ Workaround*

**Check your auto mode rules:** Run `/permissions` and open the new Auto mode tab to see exactly what the classifier auto-approves. Edit rules there instead of hunting through settings files.
*Source: [ClaudeDevs](https://x.com/ClaudeDevs/status/2093480630801858750) — ✅ Official*

## 🧭 Bottom Line

**Most important update:** The **rate limit change** (Sept 14). If you're on the 50% promo, plan for 17% less capacity. Budget your weekly usage accordingly or consider Max/Enterprise if you're consistently hitting limits.

**Most useful workflow improvement:** **`promptCacheTtl` controls** (v2.1.243). API-key users running long sessions will see real cost savings from 1-hour caching. The `/usage` loop breakdown is a close second for anyone using `/loop` regularly.

**Most important model-related change:** No new model this week, but the **auto mode security bypass research** is the most consequential model-adjacent finding — it affects how much you should trust the default permission mode with Opus 5.

**Overhyped / low-signal:** The "permanent 25% increase" framing. It's a decrease from current levels. Read the math, not the headline.

**What developers should try now:**
1. Set `promptCacheTtl: "1h"` if you use API keys
2. Open `/permissions` → Auto mode tab and review your classifier rules
3. Try `--restricted` mode if you're embedding Claude Code in CI or automation
4. Check `/usage` loop breakdowns if you run agentic loops — you may be burning tokens you didn't know about

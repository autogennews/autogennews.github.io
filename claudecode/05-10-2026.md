# Claude Code News Digest: Sep 28 – Oct 5, 2026

The Claude Code release notes for 2.1.284 to 2.1.290 (the seven versions published in the window) are the main source for this edition. I read all seven in full.

I could not open claude.com/blog, X, Hacker News, Reddit or the anthropic.com and code.claude.com pages directly, because I had no page-fetch tool. ## 🚀 What Actually Mattered

### 1. Claude Mods: plugins can now rewrite Claude Code's behavior and UI (Oct 1, v2.1.287)
- **What it does:** A mod is a small TypeScript function, shipped inside a plugin. It can rewrite a prompt, add UI, replace a built-in feature, or add new functionality ([Claude blog, search snippet](https://claude.com/blog/claude-code-mods#:~:text=A%20mod%20can%20rewrite%20a%20prompt%2C%20add%20new%20UI%2C%20replace%20a%20built%2Din%20feature%2C%20or%20add%20entirely%20new%20functionality)). You can also ask Claude Code to write, install and hot-reload one for you ([blog](https://claude.com/blog/claude-code-mods#:~:text=You%20can%20also%20use%20Claude%20Code%20to%20mod%20Claude%20Code)). The release note is [Added Claude Mods: plugins may now modify deeper behavior](https://github.com/anthropics/claude-code/releases/tag/v2.1.287#:~:text=Added%20Claude%20Mods%3A%20plugins%20may%20now%20modify%20deeper%20behavior).
- **Why it matters:** Hooks could not rewrite events or draw UI, and mods can. You can add a risky-command guard, secret redaction on tool output, or custom panes. The public design thread says a mod is just a plugin that uses function hooks ([issue #91870](https://github.com/anthropics/claude-code/issues/91870#:~:text=A%20mod%20is%20just%20a%20plugin%20that%20uses%20function%20hooks)).
- **Security:** Anthropic says [mods run with the same access to your machine as Claude Code itself](https://claude.com/blog/claude-code-mods#:~:text=Mods%20run%20with%20the%20same%20access%20to%20your%20machine%20as%20Claude%20Code%20itself). Two follow-up fixes shipped in the same week:
  - [A deny or ask rule on a nested part of a compound shell command now holds over a user-installed mod's approval on managed machines](https://github.com/anthropics/claude-code/releases/tag/v2.1.289#:~:text=Fixed%20a%20deny%20or%20ask%20rule%20on%20a%20nested%20part%20of%20a%20compound%20shell%20command) (v2.1.289).
  - [A user-installed mod that could make an organization's guard skip its check is now unloaded](https://github.com/anthropics/claude-code/releases/tag/v2.1.290#:~:text=Fixed%20a%20case%20where%20a%20user%2Dinstalled%20mod%20could%20make%20an%20organization) (v2.1.290).
- **Also in 2.1.287:** a built-in mod called "You should know", where [a side agent watches your back and flags things you or Claude might miss](https://github.com/anthropics/claude-code/releases/tag/v2.1.287#:~:text=Added%20You%20should%20know%2C%20a%20built%2Din%20mod%20where%20a%20side%20agent%20watches%20your%20back). It is opt-in via `/plugin enable`, and the note says it is for first-party sessions with telemetry on.
- **Status:** mixed. The release notes, blog snippet and issue thread confirm the feature. The "on by default" and ecosystem-size claims come from [community write-ups](https://threatfrontier.com/articles/claude-code-mods-unsandboxed-plugins-on-by-default#:~:text=Mods%20are%20on%20by%20default%20from%20that%20version).

### 2. Claude Sonnet 5.5 arrives in Claude Code (Sep 28, v2.1.284)
- **What it does:** Claude Code 2.1.284 [added Claude Sonnet 5.5 (`claude-sonnet-5-5`), now the default Sonnet model on the Anthropic API, with 1M context and $2/$10 per Mtok](https://github.com/anthropics/claude-code/releases/tag/v2.1.284#:~:text=Added%20Claude%20Sonnet%205.5). In 2.1.287, [Sonnet 5.5 can now advise Opus 4.7 and 4.8](https://github.com/anthropics/claude-code/releases/tag/v2.1.287#:~:text=Sonnet%205.5%20can%20now%20advise%20Opus%204.7%20and%204.8) through `/advisor`.
- **Why it matters:** It costs half of Opus 5.5 per token, so it is a cheaper default for long agent loops. Press coverage reports [the same $2/$10 price as Sonnet 5, faster output, and defaults of Medium effort in Claude Code](https://www.testingcatalog.com/anthropic-launches-claude-sonnet-5-5-with-faster-output/#:~:text=Default%20effort%20is%20Medium%20in%20Claude%20Code%20and%20Claude%20apps).
- **Caveat on the headline number:** The 70.6% Terminal-Bench 4.0 score is a vendor figure reported at max effort. One analysis notes [the headline scores are max-effort results, not what the API default delivers](https://www.digitalapplied.com/blog/claude-sonnet-5-5-launch-pricing-benchmarks-2026#:~:text=The%20headline%20scores%20are%20max%2Deffort%20results%2C%20not%20what%20the%20API%20default%20delivers). It puts the score at 43.0% at high effort.
- **Status:** mixed. The model ID, default status and price are in the release notes. Speed, benchmark and effort-default details come from [Reuters](https://www.reuters.com/technology/anthropic-rolls-out-second-claude-55-model-it-builds-toward-ipo-2026-09-28/#:~:text=Anthropic%20on%20Monday%20released%20Claude%20Sonnet%205.5) and other secondary coverage. I could not open anthropic.com directly.

### 3. Sessions now start in auto mode by default (Sep 28, v2.1.284, extended in v2.1.285)
- **What it does:** [Interactive terminal and VS Code sessions start in auto mode when no permission mode is configured, on every plan and provider](https://github.com/anthropics/claude-code/releases/tag/v2.1.284#:~:text=Changed%20interactive%20terminal%20and%20VS%20Code%20sessions%20to%20start%20in%20auto%20mode%20when%20no%20permission%20mode%20is%20configured). `permissions.defaultMode` still overrides it. In 2.1.285, [`claude -p` and Python Agent SDK sessions on third-party providers or with telemetry off also start in auto mode, like interactive sessions](https://github.com/anthropics/claude-code/releases/tag/v2.1.285#:~:text=to%20start%20in%20auto%20mode%20when%20no%20permission%20mode%20is%20configured%2C%20like%20interactive%20sessions).
- **Why it matters:** If you never set a permission mode, your default posture changed, and so did headless and CI behavior. Pin `permissions.defaultMode` if you want the old behavior. The prompt for reads outside the working directory also gained [a "Yes, but ask again next time" answer](https://github.com/anthropics/claude-code/releases/tag/v2.1.284#:~:text=ask%20again%20next%20time).
- **Status:** official.

### 4. 1M context becomes the default on gateways and cloud providers (Oct 1 and Sep 29, v2.1.287 and v2.1.285)
- **What it does:** On Bedrock, Vertex, Foundry and the Claude apps gateway, [Opus 4.7+ and Fable now use a 1M context window by default](https://github.com/anthropics/claude-code/releases/tag/v2.1.287#:~:text=to%20use%20a%201M%20context%20window%20by%20default%20on%20Bedrock%2C%20Vertex%2C%20Foundry), and `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` keeps 200K. Sessions behind a custom `ANTHROPIC_BASE_URL` also [use the 1M window of models that have one](https://github.com/anthropics/claude-code/releases/tag/v2.1.285#:~:text=to%20use%20the%201M%20context%20window%20of%20models%20that%20have%20one). The 2.1.285 note says to run `/autocompact 200k` if your gateway stops at 200K.
- **Why it matters:** This is a possible breaking change for proxy and enterprise setups. Longer context changes cost and compaction behavior, and a gateway that caps at 200K may now fail.
- **Status:** official.

### 5. Long-session reliability: compaction, resume and retries (Sep 28 – Oct 5, v2.1.284–290)
- **What it does:** The main fixes:
  - After a failed compaction, [Claude Code now compacts once more, keeping less of the recent conversation](https://github.com/anthropics/claude-code/releases/tag/v2.1.284#:~:text=Claude%20Code%20now%20compacts%20once%20more).
  - `--resume` and `--continue` no longer [sometimes lose every turn after a batch of parallel tool calls when the earlier session crashed](https://github.com/anthropics/claude-code/releases/tag/v2.1.286#:~:text=sometimes%20losing%20every%20turn%20after%20a%20batch%20of%20parallel%20tool%20calls).
  - After mid-response API timeouts, [non-interactive sessions and subagents now continue from the partial response](https://github.com/anthropics/claude-code/releases/tag/v2.1.288#:~:text=non%2Dinteractive%20sessions%20and%20subagents%20now%20continue%20from%20the%20partial%20response).
  - [Scheduled tasks (`/loop`, reminders) no longer silently disappear on resume once the conversation was compacted](https://github.com/anthropics/claude-code/releases/tag/v2.1.290#:~:text=silently%20not%20coming%20back%20on%20resume%20once%20the%20conversation%20was%20compacted).
- **Why it matters:** These help long unattended runs, background agents and `/loop` workflows. They are the failures that waste a whole session.
- **Status:** official.

### 6. Permission and sandbox hardening across three releases (Oct 2 – Oct 5, v2.1.288–290)
- **What it does:** The fixes include:
  - A dangerous `rm` inside `bash -c` was [running without a prompt in bypassPermissions mode or under a shell allow rule](https://github.com/anthropics/claude-code/releases/tag/v2.1.288#:~:text=running%20without%20a%20prompt%20in%20bypassPermissions%20mode%20or%20under%20a%20shell%20allow%20rule), and that is now fixed.
  - Bash deny and ask rules were [missing a command behind an environment variable prefix](https://github.com/anthropics/claude-code/releases/tag/v2.1.289#:~:text=Fixed%20Bash%20deny%20and%20ask%20rules%20missing%20a%20command%20behind%20an%20environment%20variable%20prefix).
  - Some read-only commands such as `rg` and `git grep` were [auto-approved even though the shell would expand their arguments as wildcards](https://github.com/anthropics/claude-code/releases/tag/v2.1.290#:~:text=whose%20arguments%20the%20shell%20would%20still%20expand%20as%20wildcards). They now prompt.
  - Permission rules and safety checks were [not applied to a tool call after a PreToolUse hook rewrote its input](https://github.com/anthropics/claude-code/releases/tag/v2.1.290#:~:text=Fixed%20some%20permission%20rules%20and%20safety%20checks%20not%20being%20applied%20to%20a%20tool%20call%20after%20a%20PreToolUse%20hook%20rewrote%20its%20input). That is fixed too.
- **Why it matters:** If you rely on deny rules, allow rules, sandbox auto-allow or bypass modes, update. Several of these were real bypasses. Together with the mods fixes, this makes 2.1.290 the one to be on.
- **Status:** official.

### 7. VS Code extension behavior changes (Sep 30 – Oct 5, v2.1.286–290)
- **What it does:** Changes include:
  - [Bookmarks](https://github.com/anthropics/claude-code/releases/tag/v2.1.286#:~:text=Added%20bookmarks): save Claude's responses in a side panel.
  - [Stop and Escape now end only the current turn](https://github.com/anthropics/claude-code/releases/tag/v2.1.286#:~:text=Changed%20Stop%20and%20Escape%20to%20end%20only%20the%20current%20turn). Background agents keep running and are stopped one by one from the agent map.
  - A "Run in background" action for a running command or sub-agent (v2.1.287).
  - [Message timestamps now show by default](https://github.com/anthropics/claude-code/releases/tag/v2.1.290#:~:text=Changed%20message%20timestamps%20to%20show%20by%20default).
- **Why it matters:** The Stop and Escape change alters muscle memory. Escape no longer kills background agents.
- **Status:** official.

## 🔧 Useful Tips & Tricks

1. **Add a `verify` skill.** Since 2.1.286, if your project or user skills include one named `verify`, [Claude is told to run it right before committing, except for docs-only and tests-only commits](https://github.com/anthropics/claude-code/releases/tag/v2.1.286#:~:text=Claude%20is%20now%20told%20to%20run%20it%20right%20before%20committing). It works as a cheap pre-commit gate. *Status: official.*
2. **Path-scoped rules now load on writes.** [Path-scoped `.claude/rules` and nested CLAUDE.md files now load when Write or Edit creates or changes a file in their scope](https://github.com/anthropics/claude-code/releases/tag/v2.1.288#:~:text=not%20loading%20when%20Write%20or%20Edit%20creates%20or%20changes%20a%20file%20in%20their%20scope). Before, only Read triggered them. Check any rules you wrote to guard new-file conventions. *Status: official.*
3. **Inspect a mod before installing it.** `claude plugin validate` now lists [each hook a mod registers at a gating site, with whether it has a `.catch`](https://github.com/anthropics/claude-code/releases/tag/v2.1.290#:~:text=each%20hook%20a%20mod%20registers%20at%20a%20gating%20site). One security write-up also suggests [starting with `claude --safe-mode` to rule mods out when something behaves oddly](https://threatfrontier.com/articles/claude-code-mods-unsandboxed-plugins-on-by-default#:~:text=to%20rule%20mods%20out%20when%20something%20behaves%20oddly). *Status: mixed. The validate output is official; the `--safe-mode` advice comes from a community article.*
4. **Treat effort as part of the model choice.** Ultracode is now [its own toggle in `/effort`](https://github.com/anthropics/claude-code/releases/tag/v2.1.284#:~:text=Changed%20Ultracode%20into%20its%20own%20toggle%20in%20%2Feffort). It no longer forces xhigh and can stay on at any effort level. Press coverage says [Medium is the default effort in Claude Code and the Claude apps](https://www.unite.ai/anthropic-releases-claude-sonnet-5-5-at-unchanged-sonnet-5-pricing/#:~:text=Defaults%20are%20Medium%20in%20Claude%20Code%20and%20the%20Claude%20apps), so benchmark numbers at max effort won't match your defaults. *Status: mixed.*
5. **Two small rescues.** Pressing Up on an empty prompt now [brings back a draft cleared with Ctrl+C](https://github.com/anthropics/claude-code/releases/tag/v2.1.288#:~:text=pressing%20Up%20on%20the%20empty%20prompt%20brings%20the%20draft%20back). `/mcp reconnect all` [retries every MCP server that failed to connect or needs authentication at once](https://github.com/anthropics/claude-code/releases/tag/v2.1.284#:~:text=to%20retry%20every%20MCP%20server%20that%20failed%20to%20connect%20or%20needs%20authentication%20at%20once). *Status: official.*

## 📅 On the Horizon

- **More built-in features may move to mod form (hinted).** The design thread says [the intent is to take further extant features as they exist in CC today and migrate them to mod form](https://github.com/anthropics/claude-code/issues/91870#:~:text=take%20further%20extant%20features%20as%20they%20exist%20in%20CC%20today%20and%20migrate%20them%20to%20mod%20form). The repo's `mods/` directory already contains [`agents-md`, `diff`, `sec-default` and `telemetry`](https://github.com/anthropics/claude-code/tree/fbe20e00e2851fc01506f54f98a8f0b875af3847/mods).
- **The mod API may keep changing (hinted).** One report says Anthropic cautions that [the Mod programming interface can change between releases](https://thearabianpost.com/anthropic-opens-claude-code-to-internal-mods/#:~:text=the%20Mod%20programming%20interface%20can%20change%20between%20releases). Recent releases keep adding hook surface, for example `serverToolUses` and `agentId` in 2.1.290. Expect churn if you build on mods. *Status: community-reported.*
- **Artifacts as a live review surface (speculative).** A secondary report says Anthropic [is exploring a new role for Claude Code artifacts](https://superpowerdaily.com/posts/anthropic-s-shihipar-explains-how-claude-code-could-coordinate-agents-through-artifacts#:~:text=Anthropic%20is%20exploring%20a%20new%20role%20for%20Claude%20Code%20artifacts) as a shared workspace. The report says the infrastructure is still being built.
- **Artifact usage promo ends Oct 15 (confirmed).** It does not apply to Claude Code: [this promotion applies only to artifacts](https://support.claude.com/en/articles/17274727-artifact-usage-promotion#:~:text=This%20promotion%20applies%20only%20to%20artifacts) you create in Claude and Claude Cowork.

## 🧭 Bottom Line

- **Most important update:** Claude Mods (v2.1.287). It makes Claude Code programmable at the event level, with real security trade-offs. Don't treat it as a plugin like any other.
- **Most useful workflow improvement:** The long-session reliability fixes (compaction, resume, retries, scheduled tasks) and the permission hardening in 2.1.288–290. Not flashy, but they affect every long or unattended session.
- **Most important model-related change:** Sonnet 5.5, now the default Sonnet in Claude Code at half Opus 5.5's per-token price. Opus 5.5 became the default Opus on Sep 22 per secondary sources, which is outside this window, so I don't count it here.
- **Overhyped or low-signal:**
  - The 70.6% Terminal-Bench figure is a max-effort vendor number.
  - Release-note entry counts (106 entries in 2.1.287, per a secondary source) are mostly noise.
  - The Oct 1–15 "50% off after artifacts" promo has nothing to do with Claude Code.
  - Viral mod security stories are partly based on the pre-release preview. One community guide notes the main security test used [version 2.1.274, the pre-release preview](https://app.stationx.net/articles/claude-code-mods#:~:text=Pluto%20tested%20version%202.1.274%2C%20the%20pre%2Drelease%20preview), so it was not run against the shipped build.
- **What developers should try now:**
  - Update to 2.1.290 or later.
  - Pin `permissions.defaultMode` if you don't want auto mode.
  - Add a `verify` skill.
  - Try Sonnet 5.5 via `/model` and compare effort levels on your own repo.
  - If you try mods, read the source and run `claude plugin validate` first. Only install mods from authors you trust.

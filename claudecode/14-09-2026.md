# Claude Code Weekly — September 8–14, 2026

**Six releases this week** (v2.1.265 → v2.1.270), a major security disclosure, a new plugin testing framework, and a usage limit change that hit on Sunday. Dense week.

---

## 🚀 What Actually Mattered

### 1. `claude plugin eval` — Built-in Plugin Testing Framework
**v2.1.269 · Sep 11**

A new command that runs your plugin against test cases, scores the results, then runs the same cases *without* the plugin to measure the delta. Answers three questions that were previously unmeasurable: does the skill trigger, does it survive model/edit changes, and does it actually outperform baseline?

- `claude plugin eval init` scaffolds an eval suite interactively
- 6 grader types: `regex`, `tool_used`, `tool_order`, `file_exists`, `llm`, `baseline`
- Outputs JSON + HTML reports; CI-gatable with `--threshold 0.8` and `--max-cost-usd 20`
- Default: 3 runs per case per arm (plugin vs. no-plugin)

**Why it matters:** Plugin/skill quality has been a trust problem — you write a skill, it *seems* to work, but you can't prove it helps or catch regressions. This makes plugins testable and CI-enforceable. If you maintain shared skills, this is the feature of the week.

**Verification:** Official — [GitHub releases](https://github.com/anthropics/claude-code/releases), [Claude Code docs](https://code.claude.com/docs/en/plugin-evals), [@ClaudeDevs](https://x.com/ClaudeDevs/status/2098500999656923145)

### 2. Usage Limits: The ~17% Effective Cut
**Effective Sep 14**

The temporary +50% weekly usage boost (running since May) expired Sep 13. Replaced by a permanent +25% increase over the pre-May baseline. Net effect: **~17% less weekly capacity than what you had last week.** Affects Pro, Max, Team, and seat-based Enterprise plans.

**Why it matters:** If you've been running heavy agentic workflows, you'll feel this. The math: you were at 150% of baseline, now you're at 125% — that's a 16.7% drop from current levels, even though Anthropic frames it as a "25% permanent raise."

**Verification:** Official — [Anthropic developer announcement, Aug 29](https://www.multichats.ai/blog/claude-cut-weekly-limits-17-and-called-it-a-25-increase-the-arithmetic); confirmed by multiple community analyses

### 3. `maxEffortLevel` — Admin-Enforceable Effort Caps
**v2.1.267 · Sep 9**

New setting (top-level or per-model in `modelSettings`) that caps effort level across all providers — Bedrock, Vertex, Foundry, direct API. Admins can enforce cost/speed limits organization-wide.

**Why it matters:** Enterprise teams running Claude Code across cloud providers now have a single knob to prevent runaway costs from high-effort calls. Previously, effort was only controllable per-session.

**Verification:** Official — [@ClaudeCodeLog](https://x.com/ClaudeCodeLog/status/2097780980719227061), [DevelopersIO analysis](https://dev.classmethod.jp/en/articles/20260910-cc-updates-v2-1-267/)

### 4. "Beltdown" Sandbox Escape Disclosure
**Published Sep 10 · Fixed in v2.1.247 (Aug 26)**

Accomplish.ai researchers published a macOS sandbox escape: opening an untrusted git repo in Claude Code could execute attacker-controlled code on the host — outside the sandbox, without a permission prompt. The mechanism: Claude Code's `git ls-files` calls during file-index refresh didn't blank `core.fsmonitor`, allowing a poisoned repo config to trigger arbitrary execution. Also reachable via indirect prompt injection.

Two CVEs assigned: **CVE-2026-54316** and **CVE-2026-45786**. Fix landed in v2.1.247 (Aug 26); if you're on any version from this week, you're patched.

**Why it matters:** Even with sandbox enabled and strictest permission mode, a single message in a poisoned repo could run arbitrary code. A stark reminder that sandboxing alone isn't sufficient — and that you should always be on the latest version.

**Verification:** Official fix confirmed — [Accomplish.ai blog](https://www.accomplish.ai/blog/beltdown-escaping-the-claude-code-sandbox/), [Forbes/Alex Konrad exclusive](https://x.com/alexrkonrad/status/2098164225189228837)

### 5. Permission Bypass Fixes (Bash `tee` & Analyzer Blind Spots)
**v2.1.269 · Sep 11**

Two security-relevant fixes:
- **`tee` bypass:** `Edit()` deny rules and write-path checks weren't applied to files written via Bash `tee`. A `Bash(tee:*)` allow rule no longer covers destinations outside working directories.
- **Analyzer blind spot:** `Read`/`Edit` deny rules could fail when `env -C`, `eval`, or similar un-analyzable commands appeared on the same line.

**Why it matters:** If you rely on deny rules to protect sensitive files (e.g., `deny: ["Edit(/data/raw/**)"]`), these were real gaps. Update to v2.1.269+.

**Verification:** Official — [GitHub releases](https://github.com/anthropics/claude-code/releases)

### 6. `--plugin-dir` Folder Support
**v2.1.265 · Sep 8**

`--plugin-dir` now accepts a folder of plugins (not just a single manifest). Each child folder with a manifest auto-loads, and adding/removing plugins is picked up live without restart.

**Why it matters:** Plugin development workflow just got much smoother — iterate on multiple plugins simultaneously without restarting sessions.

**Verification:** Official — [@ClaudeCodeLog](https://x.com/ClaudeCodeLog/status/2097429215209455962)

### 7. `--system-prompt-snapshot off`
**v2.1.267 · Sep 9**

Re-renders the system prompt on each request instead of snapshotting it once. Enables faster prompt iteration during development.

**Why it matters:** If you're developing custom system prompts, skills, or hooks, you no longer need to restart sessions to test prompt changes.

**Verification:** Official — [@ClaudeCodeLog](https://x.com/ClaudeCodeLog/status/2097780980719227061)

### 8. Bash Edit Diffs (`bashEditDiffEnabled`)
**v2.1.269 · Sep 11**

When Bash handles file edits (e.g., via `sed`, `awk`), the tool result now includes a diff of changed files.

**Why it matters:** Claude Code's auto mode has been increasingly routing edits through Bash instead of the `Edit` tool. This was a visibility gap — you couldn't easily see what shell commands actually changed. Now you can, and hooks keyed on file changes work better.

**Verification:** Official — [GitHub releases](https://github.com/anthropics/claude-code/releases)

### 10. Workflow Concurrency Control
**v2.1.269 · Sep 11**

## 🔧 Useful Tips & Tricks

**`/skill-doctor` for context auditing** (v2.1.261, Sep 4 — still fresh)
Run `/skill-doctor` to see which loaded skills were never invoked in your session and what each costs in context tokens. If you have 10+ skills loaded, some are probably just burning context for nothing.
*Source: [Official changelog](https://www.implicator.ai/anthropic-claude-code-skill-doctor-context-audit/) · Official*

**`bashOutputMaxChars` up to 128K** (v2.1.261)
Set `bashOutputMaxChars` in settings.json (up to 128,000) to pass long command output inline instead of truncating to a file. Particularly useful for multi-agent workflows where subagents were hitting output limits.
*Source: [Official changelog](https://aisuccesslabjuliangoldie.com/blog/claude-code-bash-output-limit/) · Official*

**Claude Code Templates now supports Function Hooks**
Community project by [@dani_avila7](https://x.com/dani_avila7/status/2097519092240384237) — install Function Hooks directly into Claude Code via the Templates npm package.
*Source: Community · community-reported*

**Harden untrusted repos beyond sandboxing**
Post-Beltdown, the practical advice: use `deny` rules to block `curl`/`wget`, route web access through `WebFetch` with domain allowlists, and set `"allowUnsandboxedCommands": false` in sandbox config. Don't rely on sandboxing as your only defense layer.
*Source: [CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-claude-code-automode-prompt-injection-2026/), [dev.to analysis](https://pivotnews.ai/five/tool-whitelists-alone-leave-claude-code-agents-exposed) · Mixed (community analysis of official features)*

## 🧭 Bottom Line

**Most important update:** `claude plugin eval` — the first native way to prove a plugin actually helps. Changes plugins from "trust me" to "here's the score." If you maintain shared skills, start writing eval suites now.

**Most useful workflow improvement:** `--system-prompt-snapshot off` + `--plugin-dir` folder support. Together they make plugin/prompt development dramatically faster — live reload without session restarts.

**Most important model-related change:** No new model this week, but **Claude Fable 5.1's 75% cache-read price cut** (from Sep 1) continues to compound savings for agentic workflows. If you haven't checked your costs since the switch, you should — heavy prompt-cache users are seeing meaningful reductions.

**Overhyped / low-signal:** The "25% permanent raise" framing of the usage limit change. It's a ~17% cut from what you had yesterday. The math is simple; the messaging was not.

**What developers should try now:**
1. Run `/skill-doctor` to audit your loaded skills — kill the ones burning context for nothing
2. If you maintain plugins: `claude plugin eval init` in your plugin directory, write 3-5 test cases, run them
3. Update to v2.1.270 if you haven't — the `tee` permission bypass and teammate trust fixes in v2.1.268-269 are security-relevant
4. Set `bashEditDiffEnabled` to get visibility into what Bash-routed edits are actually changing

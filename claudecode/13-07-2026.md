## 🚀 What Actually Mattered

### 1. In-App Browser Lands on Claude Code Desktop
- **What it does:** Claude Code Desktop now has a sandboxed, tabbed browser built in. Claude can open docs, designs, or any website and read, click through, and interact with pages — the same way it already worked with local dev server previews. Open with `Cmd+Shift+B` (macOS) / `Ctrl+Shift+B` (Windows). Session persistence is configurable; safety classifiers review actions on external sites.
- **Why it matters:** This is the biggest UX change in weeks. You no longer need to copy-paste documentation URLs or screenshots into context — Claude can browse reference material itself mid-task. For frontend work, it can now inspect live designs alongside your code. Moves Claude Code meaningfully closer to a full build→test→debug→reference loop without leaving the tool.
- **Verification:** ✅ Official — [Claude Code Docs, Week 28](https://code.claude.com/docs/en/whats-new/2026-w28), [@ClaudeDevs on X](https://x.com/ClaudeDevs/status/2075635283211772279)

---

### 2. `/doctor` Upgraded: Now Diagnoses AND Fixes Issues
- **What it does:** The `/doctor` command (alias `/checkup`) is no longer read-only. It now checks installation health, identifies unused skills/MCP servers/plugins, deduplicates `CLAUDE.md` files, proposes trimming derivable content, flags slow hooks, and can apply fixes — with confirmation before changes.
- **Why it matters:** Previously you'd see a wall of diagnostics and have to fix things manually. Now it's actionable. Especially useful for teams onboarding new devs or maintaining complex multi-MCP setups that accumulate cruft.
- **Verification:** ✅ Official — [Claude Code Docs, Week 28](https://code.claude.com/docs/en/whats-new/2026-w28)

---

### 3. Auto Mode Transcript Tampering Protections
- **What it does:** Auto mode now blocks transcript tampering and prompts before running destructive commands (like `rm -rf`) on unresolved variables. Background task notifications explicitly state that no human input occurred, preventing fabricated transcript approvals.
- **Why it matters:** This is a real safety improvement for anyone running Claude Code in autonomous/headless modes. As loop-based workflows become more common, the attack surface for prompt injection via tampered transcripts grows — this directly addresses that.
- **Verification:** ✅ Official — [Claude Code Docs, Week 28](https://code.claude.com/docs/en/whats-new/2026-w28)

## 🔧 Useful Tips & Tricks

### Fable 5 as Orchestrator, Cheap Models as Executors
Anthropic benchmarked this pattern: **96% of full-Fable performance at 46% of the cost.** Setup: set Fable 5 as your main model, create sub-agent files in `.claude/agents/` with `model: sonnet` or `model: opus` frontmatter, add a `CLAUDE.md` policy directing Fable to only plan and review (never write code directly). Sonnet handles boilerplate; Opus handles complex reasoning.
- **Source:** [Reddit r/ClaudeAI](https://www.reddit.com/r/ClaudeAI/comments/1ur2ml9/anthropic_just_benchmarked_fable_5_orchestrates/), [Data Science Dojo](https://datasciencedojo.com/blog/claude-code-fable-5-orchestrator-workflow/)
- **Status:** ✅ Confirmed pattern, officially benchmarked

### Caveman Mode: Overhyped Token Savings
The viral "Caveman" skill (87K+ GitHub stars) claims 65% token savings. **JetBrains tested it and found only ~8.5% savings on real coding tasks.** The 65% figure applies to chat-style Q&A, not code generation where tokens are dominated by code, diffs, and tool calls. It's safe to use (no quality damage, p=0.82 across 82 paired tasks) but won't meaningfully cut your bill.
- **Source:** [JetBrains blog](https://blog.jetbrains.com/ai/2026/07/speak-to-ai-agents-like-cavemen-tosave-tokens/), [The New Stack](https://thenewstack.io/caveman-mode-token-savings/)
- **Status:** ✅ Independently verified debunk

### Context Discipline > Token Hacks
Community consensus is hardening: run `/compact` at **70% context** (precision starts degrading) and `/clear` at **90%** (hallucinations spike). A tight `CLAUDE.md` plus scoped folder pointers saves more than any output-compression plugin.
- **Source:** [FlorianBruniaux/claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide), multiple community threads
- **Status:** 🟡 Community best practice, consistent with official guidance

### MCP Security: 28 CVEs, 655 Malicious Skills Reported
Vet all MCP servers before adoption. The community guide recommends a 5-minute audit checklist before adding any MCP integration.
- **Source:** [claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide)
- **Status:** 🟡 Community-reported numbers; exercise caution

## 🧭 Bottom Line

- **Most important update:** **In-app browser on Desktop.** It fundamentally changes how Claude Code interacts with external information — docs, designs, live sites — without context-window copy-paste overhead.

- **Most useful workflow improvement:** **Fable 5 orchestrator + sub-agent pattern.** If you're on a paid plan, you have until July 19 to use Fable 5 at no extra cost. Set it as planner/reviewer, delegate execution to Sonnet. Anthropic's own benchmarks show 96% quality at 46% cost.

- **Most important model-related change:** **Fable 5 access extension to July 19 with 50% higher Claude Code rate limits.** This is a direct competitive response to GPT-5.6 Sol and gives Claude Code users materially more headroom this week.

- **Overhyped / low-signal:** **Caveman mode.** Fun, harmless, but JetBrains proved the 65% savings claim doesn't hold for coding tasks (~8.5% actual). Context discipline matters more. Also, the "loop engineering" discourse is generating more content-marketing than actionable insight — the official loops guide is useful, the influencer ecosystem around it is noise.

- **What developers should try now:**
  1. Open the in-app browser (`Cmd+Shift+B`) and point Claude at your API docs during a real task
  2. Run `/doctor` to clean up accumulated MCP/skill/CLAUDE.md cruft
  3. If you haven't tried the Fable 5 orchestrator pattern, set it up before July 19 — it's the best cost/quality tradeoff available right now
  4. Review your auto-mode workflows in light of the new transcript protections — if you're running headless loops, the safety improvements are meaningful
